# Algae Bloom Detection System

Satellite-based monitoring and classification of harmful algal bloom (HAB) conditions in Lake Erie using Sentinel-2 imagery, spectral features, CyAN reference data, and machine-learning experiments.

> **Project status:** This repository is an organized publication of the notebooks supplied for this project. The uploaded archive contained notebooks only. Required datasets, CyAN GeoTIFFs, trained model weights, and final result images were not included, so the workflow is not fully runnable from this repository alone yet.

## Project overview

Harmful algal blooms can vary across large water bodies and over time. This project explores a satellite-based workflow for identifying bloom-related patterns over Lake Erie. It uses Sentinel-2 imagery and spectral information, with CyAN data used in the dataset-labeling workflow.

The supplied notebooks cover dataset generation, data preparation, spiking-neural-network (SNN) experiments, Bayesian comparison, ensemble experiments, evaluation, and an interactive inference viewer.

## Workflow

1. **Dataset generation** – retrieve and process Sentinel-2 imagery through Google Earth Engine, compute spectral features, and use CyAN raster data for reference labels.
2. **Dataset preparation** – prepare the generated tabular data for model experiments and apply the augmentation/preparation steps implemented in the notebook.
3. **Model training** – train the SNN model using the feature-selection and training workflow in the notebook.
4. **Bayesian comparison** – compare the baseline and Bayesian-optimization experiments.
5. **Ensemble experiments** – evaluate the ensemble approach implemented in the notebook.
6. **Evaluation** – generate model evaluation outputs and visualizations.
7. **Interactive viewer** – use Google Earth Engine and a trained model to inspect a selected Lake Erie region and date.

## Setup

### 1. Clone the repository

```bash
git clone https://github.com/YOUR_USERNAME/algae-bloom-detection.git
cd algae-bloom-detection
```

### 2. Install dependencies

```bash
python -m venv .venv
```

Activate the environment:

- Windows PowerShell: `.venv\\Scripts\\Activate.ps1`
- macOS/Linux: `source .venv/bin/activate`

Then install:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Some notebooks use `google.colab` and are intended to run in Google Colab rather than a local Python environment. For those notebooks, open the notebook in Colab and install any notebook-specific packages if prompted.

### 3. Configure Google Earth Engine

The dataset-generation and interactive-viewer workflows use the Earth Engine Python API. You need:

- A Google account with access to Google Earth Engine.
- An Earth Engine-enabled Google Cloud project.
- Authentication in the notebook environment.

In the notebooks, replace `YOUR_GEE_PROJECT_ID` with your own Earth Engine Cloud project ID. Do not commit credentials, service-account keys, or access tokens.

## Data and model files

The original ZIP did not include the source datasets or trained weights. Before reproducing the experiments, obtain the project data and model files from their authorized source and place them where the relevant notebook expects them.

- **Satellite data:** accessed through Google Earth Engine in the dataset-generation and viewer notebooks.
- **CyAN reference rasters:** required by the labeling section of the dataset-generation notebook.
- **Tabular datasets:** the notebooks reference CSV files generated or supplied separately.
- **Trained model:** the interactive viewer expects a trained SNN model file. Update its configured model path to match your file.

Large raw datasets, GeoTIFFs, and model checkpoints are intentionally excluded from Git by `.gitignore`. If you publish them, use an appropriate data/model hosting service and document the download instructions here.

See [`data/README.md`](data/README.md) for expected data guidance.

## Important reproducibility notes

- Exact outputs depend on the Sentinel-2 scenes available for the selected dates, cloud filtering, sampling configuration, and the supplied CyAN rasters.
- The notebooks may need path changes when run outside the original Google Colab environment.
- The repository does not currently contain the datasets or trained model weights, so a fresh clone is not yet a complete end-to-end reproduction.
- Review notebook cells for environment-specific paths and run the notebooks in the documented order.
